🎯 Problem Definition & Opportunity

Six hands-on activities to turn messy research into well-defined problems. Practise affinity mapping, POV, HMW, stakeholder mapping, 5 Whys, and problem selection.

Students will be able to analyze user research, identify root causes, frame well-defined problems, and recognize opportunities for innovative solutions.

🧪 Activity 2.1Unit II

Affinity Mapping of Interview Data

⏱ 45 min👥 Group📘 § 2.1
Name:
Roll No.:
Date:
Topic:

🎯 Objective

Group raw observations from user research into themes to reveal patterns and generate insights.

🧰 Materials

  • ☐ Interview notes (from U1)
  • ☐ Sticky notes
  • ☐ Wall or whiteboard
  • ☐ Marker

📋 Steps

  1. Write every observation from your interviews on a separate sticky note — one fact per note.
  2. Stick all notes on the wall randomly.
  3. In silence, move notes that feel similar into clusters.
  4. Give each cluster a short theme name.
  5. Write one insight sentence under each theme (the WHY behind the pattern).
  6. Note the top 3 themes that appear most often.

🧩 Theme Clusters

Insight (why):
3Theme:
Insight (why):
4Theme:
Insight (why):

🧠 Reflection

1. Which theme surprised the group the most?
2. Which insight could become a real design opportunity?

⚠️ Common Mistakes

  • Writing multiple facts on one sticky note — breaks clustering.
  • Naming themes with vague labels ("general problems").
  • Skipping the insight step — themes without "why" are useless.

🧪 Activity 2.2Unit II

Develop Three Alternative Problem Statements

⏱ 40 min👥 Individual📘 § 2.2
Name:
Roll No.:
Date:
Theme:

🎯 Objective

Write three different problem statements for the same theme — showing how framing changes the direction of solutions.

🧰 Materials

  • ☐ Affinity map (2.1)
  • ☐ Notebook
  • ☐ Pen
  • ☐ Problem statement format card

📋 Steps

  1. Pick the strongest theme from Activity 2.1.
  2. Recall the format: [User] needs [need] because [insight].
  3. Write problem statement #1 — the obvious one.
  4. Write #2 — flip the user to a different stakeholder.
  5. Write #3 — flip the need to a deeper underlying need.
  6. Circle the one that feels most actionable.

📝 Three Statements

1[User] needs [need] because [insight]
 
2[User] needs [need] because [insight]
 
3[User] needs [need] because [insight]
 

🧠 Reflection

1. Which statement was hardest to write? Why?
2. How does changing the framing change possible solutions?

⚠️ Common Mistakes

  • Writing 3 versions of the same statement.
  • Using vague users ("people", "everyone").
  • Leaving out the insight — turns the statement into a wish.

🧪 Activity 2.3Unit II

Prepare POV and HMW Statements

⏱ 45 min👥 Individual📘 § 2.3
Name:
Roll No.:
Date:
Problem:

🎯 Objective

Convert a problem statement into a POV sentence and then into multiple HMW questions — the bridge from research to ideation.

🧰 Materials

  • ☐ Problem statements (2.2)
  • ☐ Notebook
  • ☐ Pen
  • ☐ HMW prompt card

📋 Steps

  1. Pick the strongest problem statement from Activity 2.2.
  2. Rewrite it as a POV: [User] needs [need] because [surprising insight].
  3. Now convert the POV into at least 5 different HMW questions.
  4. Vary each HMW — one focused on time, one on cost, one on emotion, one on technology, one wildcard.
  5. Circle the HMW that feels most energising to you.

💬 POV Statement

❓ My HMW Questions

1How might we…
2How might we…
3How might we…
4How might we…
5How might we…

🧠 Reflection

1. Which HMW opened the most creative space?
2. Which HMW would you start ideating on tomorrow?

⚠️ Common Mistakes

  • Writing HMW as yes/no questions — kills ideation.
  • HMW too narrow ("How might we build an app…") — locks the solution.
  • Only writing one HMW — the first one is rarely the best.

🧪 Activity 2.4Unit II

Stakeholder Map

⏱ 40 min👥 Individual / Group📘 § 2.4
Name:
Roll No.:
Date:
Project:

🎯 Objective

Identify every person affected by the problem, then classify them by influence and interest — so no one important is ignored.

🧰 Materials

  • ☐ A4 sheet
  • ☐ Pencil + ruler
  • ☐ Sticky notes
  • ☐ Project brief

📋 Steps

  1. List every person or group touched by your problem — users, buyers, family, staff, regulators, competitors.
  2. Draw a 2×2 grid on paper: axes = Influence (vertical) and Interest (horizontal).
  3. Place each stakeholder in one quadrant.
  4. Label each quadrant with its action: Manage Closely / Keep Satisfied / Keep Informed / Monitor.
  5. Circle the 3 most critical stakeholders.

📊 Stakeholder Grid

⭐MANAGE CLOSELY — high influence, high interest:
 
👥KEEP SATISFIED — high influence, low interest:
 
📢KEEP INFORMED — low influence, high interest:
 
👀MONITOR — low influence, low interest:
 

🧠 Reflection

1. Who did you initially forget, but belongs in the map?
2. Which stakeholder could block or boost your solution?

⚠️ Common Mistakes

  • Listing only the end user — missing stakeholders mean missing constraints.
  • Placing everyone in "Manage Closely".
  • Confusing influence with power.

🧪 Activity 2.5Unit II

Root-Cause Analysis (5 Whys)

⏱ 40 min👥 Individual / Group📘 § 2.4
Name:
Roll No.:
Date:
Problem:

🎯 Objective

Trace a visible problem back to its root cause by asking "Why?" five times — so you fix the cause, not the symptom.

🧰 Materials

  • ☐ Notebook
  • ☐ Pen
  • ☐ Problem statement
  • ☐ Evidence (data/notes)

📋 Steps

  1. Write the visible problem at the top of a page.
  2. Ask "Why does this happen?" — write the answer.
  3. Ask "Why?" on that answer — write the next.
  4. Continue until you have asked "Why?" five times.
  5. Circle the deepest answer — that is your root cause.
  6. Write one countermeasure that would fix the root cause.

🌳 The Why Chain

PProblem:
1Why?   →  
2Why?   →  
3Why?   →  
4Why?   →  
5Why?   →   🎯 root cause

💡 Proposed Countermeasure

🧠 Reflection

1. Did the root cause surprise you?
2. Why is fixing symptoms only a temporary solution?

⚠️ Common Mistakes

  • Stopping at 2–3 whys — you reach the mid-cause, not the root.
  • Changing the question midway — must always be "Why?"
  • Guessing answers instead of using real data.

🧪 Activity 2.6Unit II

Select and Validate One Problem / Opportunity

⏱ 50 min👥 Group📘 § 2.5 · 2.6 · 2.8
Name:
Roll No.:
Date:
Team:

🎯 Objective

Narrow down all candidate problems to one, then validate it with real users before locking in.

🧰 Materials

  • ☐ All statements (2.2)
  • ☐ Need-opportunity grid
  • ☐ 3 users to talk to
  • ☐ Consent script

📋 Steps

  1. List all candidate problems on one page.
  2. Score each on Impact (1–5) and Feasibility (1–5).
  3. Plot on the need-opportunity matrix.
  4. Pick the one in the top-right quadrant — Quick Win.
  5. Talk to 3 real users for 5 minutes each: ask, "Do you face this? How often?"
  6. If at least 2 of 3 confirm, your problem is validated. If not, pick another candidate.

🎯 Final Selected Problem

🧠 Reflection

1. Did validation change your choice?
2. What evidence do you have that this problem is real?

⚠️ Common Mistakes

  • Picking a problem because it sounds "cool" instead of high-impact.
  • Skipping validation — building on assumptions.
  • Asking leading questions during validation.
